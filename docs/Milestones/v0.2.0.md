## 🎯 Purpose and outcome

Consolidate the Excel/VBA prototype of the Basel standardized approach into
an evaluated baseline that informs the regulatory-scope and platform
decisions of v0.3.0. The prototype covers SBM delta, vega and curvature for
GIRR, CSR non-securitization, equity, commodity and FX under the three
correlation scenarios, the non-securitization default risk charge and the
residual risk add-on (MAR21–MAR23).

Completion means the prototype has been built, compiled and run in desktop
Excel, reconciles with the independent reference, survives a verified source
round trip, and has its limits written down. It does not mean the
calculation is certified, complete for any jurisdiction or fit for
regulatory reporting. The workbook reports version `0.2.0-prototype` (#113).

## 🔗 Dependencies and order

The engine (#20) and its input fixes come first; the template layout (#30)
and style (#76) fix what the build produces. The tools (#72, #79, #82) let
one Excel run serve every remaining criterion. #28 then records that run,
and #20, #30, #72, #79, #82 and #85 close on its evidence; none of them needs
to close before #28 runs. The closeout (#32) reconciles everything last.

Freeze one candidate commit before the Excel run. Evidence from another
commit, or from LibreOffice, does not count for the Excel criteria. A change
to the template or the modules after the run needs the affected checks again.

Task PRs target `release/v0.2.0` and squash-merge under
[governance](../GOVERNANCE.md). Integration into main happens only on the
owner's explicit request, through a merge-commit PR, after which main is
brought back into the release branch through a reviewed merge-commit PR.

## ✅ Exit criteria and evidence

Issue #32 must link evidence that:

- #28 records one desktop Excel run on a frozen candidate, in the
  [Excel evidence](../EXCEL_EVIDENCE.md) format, and
  `tools/check_excel_evidence.py` accepts it.
- On that candidate: the build with `-RunTests` exits 0, **Debug → Compile**
  passes in the development and production builds, the regression test
  passes 52 of 52 items, and the round trip passes in both modes with a
  verified workbook binding.
- The LibreOffice reconciliation, the hand-calculated tests and the template
  checks pass on the same candidate.
- Every milestone issue is closed with its evidence, or names the gap that
  remains, with the owner as assignee and one priority.
- The [evaluation](../evidence/2026-10-27-prototype-evaluation.md) is
  complete: coverage, Excel results, the build effort and its risks, the
  template, worksheet access in the core modules and the known limits.
- CHANGELOG and the roadmap match the merged work and claim no regulatory
  validation.

Use commit-bound evidence: name the PR or commit, commands, results, hosted
run URLs and anything not run. LibreOffice runs are not Excel evidence, and
agreement with the reference does not prove the reading of the regulation.
Never fabricate workbook or Excel results.

## ⏸️ Deferred work and decisions

- **Methodology interpretations (#29):** six readings of MAR21–MAR23 stay
  open and are documented as prototype limits in the
  [methodology](../methodology.md#interpretations-and-simplifications-to-review).
  Deciding them belongs to v0.3.0.
- **Out of scope:** CSR securitization, the correlation trading portfolio,
  securitization DRC, any jurisdiction profile, pricing of sensitivities or
  CVRs, and large-portfolio performance.
- **Long-term platform:** the prototype informs the decision; making it is
  the owner's, in v0.3.0.
- **Release:** no tag, GitHub release or workbook distribution is part of
  this milestone unless the owner requests it under
  [Releasing](../../RELEASING.md).

## 📋 Closeout and transition

The [interim evaluation](../evidence/2026-10-27-prototype-evaluation.md)
records the state on October 27, 2026, before any Excel run. The final
closeout record adds the #28 evidence and replaces the interim assessment
where they differ. Closing this milestone does not merge main, create a tag
or select the next platform. Once the milestone is closed and fully
integrated, `release/v0.1.0` and then `release/v0.2.0` become obsolete and
are deleted under the
[release-branch lifecycle](../GOVERNANCE.md#release-branch-lifecycle).
