## 👀 Checks by eye

In the development workbook:

* **Run FRTB-SA:** 0 errors and 0 warnings. The total capital requirement is
  3.877.793, the expected 3,877,792.81 at the sheet's format, with SBM
  3.163.703 (binding scenario LOW), DRC 636.589 and RRAO 77.500.
* **Run regression test:** "Result: PASS (52 items)" on `Test_Expected`, every
  item with an absolute difference of 0,00.
* **Clear outputs:** the output sheets keep their headers and placeholder.
* **Failed run:** with one `P_GIRR` risk weight cleared, **Run FRTB-SA**
  stops with "Calculation failed: Error -2147219456: Invalid numeric
  parameter in [GIRR_RW] data row 1, column 2 (P_GIRR): blank". Results C6
  and the Log entry were not separately recorded.
* **`RefReportingCcy` (#176):** with `FX_CURVATURE_DIVISOR` TRUE on
  `Control`, I set the flag of the GBP row `C009` on `In_Curvature` (CVR up
  15,000, CVR down 12,000) and ran after each value. Its FX curvature `Kb`
  on `Out_Buckets`:

  | Flag | Result |
  | --- | --- |
  | blank | `Kb` 10.000: divided by 1.5 |
  | `TRUE` | `Kb` 15.000: not divided, no error |
  | `1` with the custom format `"TRUE";"TRUE";"FALSE"` | as for `TRUE` |
  | `2` with that format | as for `TRUE` |
  | `1` with the General format | row rejected: 1 error on `Log` |
  | `YES` | row rejected: 1 error on `Log` |

  This is the numeric path of `IsBlankOrBoolCell` and `CellBool`, which
  LibreOffice does not take. The screenshots show the divided and undivided
  values and the rejection; I confirmed each case. The FX curvature class
  charge stays 0 in every case, as in the sample: aggregated with the
  negative USD bucket, its total is floored at zero.
* **Regional settings:** with the comma decimal separator, `P_General` shows
  `1,25`, `0,75` and `55,0%`, and the sample runs without error.
* **Presentation:** the buttons run, the tab colors are applied (inputs and
  parameters gold, outputs blue) and the panes are frozen. Two layout
  findings, with no effect on any value:
  * on `Results`, the frozen column runs through the table, between
    "Risk class" and "Component";
  * on `Control`, the Description column cuts off its longer texts.

  Both are fixed by #203 on `release/v0.3.0`, after this candidate.
